# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`carllib` is an early-stage C++23 library for **Cellular Automata and Reinforcement Learning with drawing capabilities**, built on SFML 3. It produces a library (`carllib::carllib`) plus one or more demo binaries under `apps/` — currently just `wolfram` (`apps/wolfram/`). The project scaffolding was generated by `cmake-init`, so most `cmake/` scripts, `BUILDING.md`, and `HACKING.md` are boilerplate from that tool.

## Build, Test, Lint

The project uses CMake presets. Developer targets (tests, lint, coverage, docs) are hidden unless `carllib_DEVELOPER_MODE=ON`, which the `dev-mode` preset sets.

Per `HACKING.md`, create a `CMakeUserPresets.json` with a `dev` preset inheriting `["dev-mode", "ci-<os>"]` (`<os>` = `win64`, `linux`, or `darwin`). Then:

```sh
cmake --preset=dev          # configure
cmake --build --preset=dev  # build
ctest --preset=dev          # run tests
```

CI uses the top-level presets directly (`ci-windows`, `ci-ubuntu`, `ci-macos`), e.g. `cmake --preset=ci-windows -D BUILD_SHARED_LIBS=YES`.

- **Single test**: There is one test *binary* (`carllib_test`) but `catch_discover_tests` registers each Catch2 `TEST_CASE` as its own ctest entry. Use `ctest --preset=dev -R <name>` to filter by test-case name (e.g. `-R wrap` for cases in `math_test.cpp`). Test sources are `test/source/{carllib,math,base_1d,wolfram}_test.cpp`.
- **Run the demo**: Build the `wolfram` target (`cmake --build --preset=dev --target wolfram`), then execute it **from the project source root** so `init.toml` and `42dotSans.ttf` resolve: `./build/dev/apps/wolfram/wolfram -r 110`. The convenience `run` target documented in older notes is commented out in the top-level `CMakeLists.txt`. CLI flags: `-r/--rule <0–255>` (required), `-z/--zoom <int>` (default 4), `--random` (random initial row instead of single center cell), `-c/--config <path>` (default `init.toml`).
- **Format**: build the `format-check` / `format-fix` targets (clang-format). CI runs `cmake -D FORMAT_COMMAND=clang-format-18 -P cmake/lint.cmake`.
- **Spell**: `spell-check` / `spell-fix` targets (codespell), or `cmake -P cmake/spell.cmake`.
- **Static analysis**: `ci-ubuntu` enables clang-tidy and cppcheck via the `CMAKE_CXX_CLANG_TIDY` / `CMAKE_CXX_CPPCHECK` cache variables; `.clang-tidy` and `.clang-format` configure them.

### Dependencies

The library itself (`carllib_carllib`) depends on **SFML 3 (Graphics)**, **spdlog**, and **tomlplusplus** via `find_package` (see top-level `CMakeLists.txt`). The `wolfram` demo additionally depends on **fmt** and **CLI11** — those `find_package` calls live in `apps/wolfram/CMakeLists.txt`, so a library-only build does not require them. Catch2 v3 is required for tests. The intended dev environment is the **Nix flake** (`flake.nix`) — `nix develop` provides gcc, cmake, ninja, and all dependencies. The flake targets `x86_64-linux` only; on Windows you must supply these dependencies yourself (e.g. via vcpkg, see `vcpkg.json`) and use the `ci-windows`/MSVC flags.

### Windows shared-library tests

When building with `BUILD_SHARED_LIBS=ON` on Windows, the DLL path (e.g. `build\dev\Debug`) must be on `PATH` before running tests. See `HACKING.md` for the `env.ps1` sourcing pattern.

## Architecture

Public headers live in `include/carllib/<module>/`, implementations in `source/` (mostly under matching `source/<module>/` subdirs — but note `cell_grid.cpp` is at `source/cell_grid.cpp`, not `source/graphics/`). There are three modules — `graphics`, `ca`, `util` — plus the top-level `carllib.hpp` placeholder. Demo binaries live in `apps/<name>/` and link against `carllib::carllib`.

### `graphics` — `carllib::graphics`

- **`window`** (`graphics/window.hpp` / `source/graphics/window.cpp`) — abstract base class that owns an `sf::RenderWindow` and runs the main loop. Construction is **two-step**: free function `graphics::create_from_config(config_file_name = "init.toml")` parses the TOML window settings and returns an `sf::RenderWindow` (it **throws `std::runtime_error`** on parse failure or window-creation failure — it does not return `std::optional`). Subclasses then pass that into the protected `window(sf::RenderWindow&&)` constructor (see `apps/wolfram/main.cpp::wolfram_window` for the canonical pattern).

  Behavior is injected via `virtual` overrides, **not** `std::function` callbacks:
  - `on_setup()` — called once before the loop starts (load fonts, init CA state, etc.).
  - `on_handle_event(const sf::Event&)` — called for each polled event. The base implementation handles `Closed` (calls `stop_loop()`) and `Resized` (rebuilds the view to match new dimensions). Overrides should delegate to `window::on_handle_event(event)` for anything they don't handle (see `wolfram_window` for the mouse-wheel-then-base pattern).
  - `on_logic()` — non-draw per-frame logic.
  - `on_draw()` — per-frame draw. Default clears to magenta and calls `display()`; overrides are responsible for both `clear` and `display`.
  - `on_teardown()` — called after the loop exits.

  `start_loop()` runs `on_setup → (poll/handle → on_logic → on_draw) loop → on_teardown` and returns an `int` exit code suitable for returning from `main`. `stop_loop()` ends the loop. The class is move-only (copy deleted, move defaulted) and has a virtual destructor. The `sf::RenderWindow` is exposed to subclasses as the protected `m_render_window` member.

- **`cell_grid`** (`graphics/cell_grid.hpp` / `source/cell_grid.cpp`) — drawable grid, inheriting `sf::Drawable` + `sf::Transformable`. Backed by a single `sf::VertexArray` of triangles: each cell is a quad = **6 vertices** (`vertices_per_quad`), indexed as `(col + row * width) * 6` via `get_first_vertex_of_position`. `resize(new_size, cell_size, randomize_colors)` rebuilds the whole buffer (dropping prior cell state) and parallel-fills cells with random colors when `randomize_colors` is `true` (uses `std::for_each(std::execution::par, ...)` with a `thread_local std::mt19937`). `set_color_at` / `get_color_at` write/read all 6 vertices of the targeted quad and return `bool` / `std::optional<sf::Color>`; out-of-range positions fail rather than throw.

### `ca` — `carllib::ca` (cellular automata)

- **`base_1d<StoredValue>`** (`ca/base_1d.hpp`, header-only template — there is no corresponding `.cpp`) — generic 1D CA with toroidal wrapping. Stores the **full generation history** in a `std::vector<std::vector<StoredValue>>`; `get_generation_data(n)` returns generation `n` by const ref, `total_generations()` returns the count. `calculate_next_generation()` is **pure virtual**, so `base_1d` cannot be instantiated directly — subclasses override it and append via the protected `add_generation()` (which throws if the new row's width doesn't match). For `StoredValue = bool`, the width + `initial_condition` constructor seeds the first generation either as a single `true` cell at `width / 2` (`initial_condition::standard`) or a Bernoulli(0.5) random row (`initial_condition::random`). Other constructors take an initializer list or input iterator pair. The `initial_condition` enum lives in this header and is reused by `wolfram` and the demo CLI.

- **`wolfram`** (`ca/wolfram.hpp` / `source/ca/wolfram.cpp`) — derives from `base_1d<bool>` and implements Wolfram **elementary 1D CA** (rule 0–255, wrapped in the `wolfram_number` strong type). Constructor takes `(wolfram_number rule, std::size_t width, initial_condition = standard)`. The triad `(left, current, right)` forms a 3-bit index; bit `triad` of the rule byte gives the next cell. Neighbors wrap toroidally (first/last cell wrap to last/first). Operands are cast to `unsigned` before bitwise ops to avoid the `hicpp-signed-bitwise` clang-tidy warning.

### `util` — `carllib::util`

- **`math.hpp`** — `wrap(value, lower, upper)` for signed integers (constrained by a `signed_integral` concept). Used for toroidal indexing in CA code.

### Top level

- **`carllib.{hpp,cpp}`** — `exported_class`, a placeholder from the cmake-init template (only exercised by `test/source/carllib_test.cpp`). Not part of the real API surface.

### `apps/wolfram` — demo binary

`apps/wolfram/main.cpp` defines an anonymous `wolfram_window` subclass of `graphics::window` that wires the Wolfram CA to a `cell_grid`. Each frame (in `on_logic`) it recomputes the visible width/height as `window_size / zoom`, extends the CA history until enough generations exist, resizes the grid to match, then paints each cell black/white from `m_wolfram_ca->get_generation_data(row)` — centering the visible window inside the wider 4000-cell ring via `std::views::drop((width_total - width_visible) / 2)`. `on_draw` clears to magenta, draws the grid, then draws an `fmt::format`-built size/zoom overlay using `42dotSans.ttf`. `on_handle_event` clamps mouse-wheel zoom to `[1, 32]` and forwards anything else to the base class. CLI parsing uses CLI11; `--random` selects `ca::initial_condition::random`.

### Export header

`CMakeLists.txt` generates `carllib/carllib_export.hpp` (via `generate_export_header`) into the build dir for symbol visibility. Static builds define `CARLLIB_STATIC_DEFINE`; visibility is hidden by default.

## Conventions

- **C++23** (`target_compile_features(... cxx_std_23)` on the library, executable, and test target — the public include is still advertised as `cxx_std_23` PUBLIC). `snake_case` for types and members (members prefixed `m_`), trailing-return-type style (`auto fn() -> T`).
- Doxygen comments on public methods.
- The compiler warning set is strict (see the `flags-*` presets): `-Wconversion -Wsign-conversion -Wold-style-cast -Wshadow` etc. on GCC/Clang, `/W4 /permissive-` plus many `/wNNNN` on MSVC. New code is expected to compile clean under these. clang-tidy is enabled in `ci-ubuntu`; `hicpp-signed-bitwise` in particular bites raw `bool`/`int` bitwise math — cast to `unsigned` (see `wolfram.cpp` for the pattern).

## Notes / Gotchas

- **The demo must be launched from the project source root.** `apps/wolfram/main.cpp` (via `sf::Font("42dotSans.ttf")`) and `create_from_config` (default `"init.toml"`) load by relative path. The `run` custom target that used to set `WORKING_DIRECTORY` is commented out in the top-level `CMakeLists.txt`, so launching `build/dev/apps/wolfram/wolfram` directly from inside `build/` will fail to load the font/config — run it from the source root instead, or pass an absolute `-c` path.
- **`create_from_config` throws, it doesn't return `std::optional`.** Older code/docs may suggest checking for `nullopt`; the current contract is exceptions on parse or window-creation failure.
- **`base_1d::calculate_next_generation` is pure virtual.** You cannot instantiate `base_1d<T>` directly even though the constructors look usable.
- The CI workflow (`.github/workflows/ci.yml`) triggers on `master`, but the working branch is `main`, and the coverage/docs jobs are gated behind `&& false` with a `<name>` placeholder — CI is effectively unconfigured for this fork.
- `README.md`, license, and homepage URL are still cmake-init placeholders.
